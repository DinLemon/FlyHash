# FlyHash на настоящей проводке: оптимизирована ли схема грибовидного тела под поиск ближайших соседей?

**Дата:** 2026-09-11
**Статус:** дизайн утверждён, к реализации
**Датасет:** male-cns v1.0 (Janelia FlyEM), лицензия CC-BY

---

## 1. Вопрос

В 2017 году Dasgupta, Stevens & Navlakha (*Science* 358:793) показали, что обонятельный контур дрозофилы реализует алгоритм хеширования с сохранением близости (LSH), и что этот алгоритм — «FlyHash» — обходит классический LSH на задаче поиска ближайших соседей.

Их модель была **идеализированной**: случайная разреженная бинарная матрица, ровно ~6 входов на клетку Кеньона, равномерное распределение, оператор «оставь топ-5%» как абстракция.

Теперь доступна **измеренная** проводка того же контура. Отсюда вопрос:

> Даёт ли настоящая связность PN→KC преимущество в поиске ближайших соседей по сравнению со случайной связностью **той же статистики**?

Вопрос распадается на два, и их принципиально важно не путать:

1. **Влияет ли распределение степеней?** У настоящих KC число входов неравномерно (см. §3). Неравномерность сама по себе может помогать или мешать — но она может быть просто побочным продуктом биологии развития, а не адаптацией.
2. **Влияет ли выбор конкретных партнёров?** Если зафиксировать каждой KC её реальное число входов, но перемешать, *кто именно* эти входы, — изменится ли качество? Положительный ответ здесь означал бы, что отбор действительно настроил конкретные пары PN→KC.

Только второй вопрос — настоящая находка. Первый — интересный, но куда более слабый.

## 2. Ожидаемый результат и почему это не важно

Наиболее вероятный исход: **значимой разницы нет**. Это полноценный и публикуемый ответ.

Второй по вероятности: FLY обгоняет UNIFORM, но не обгоняет SHUFFLED — то есть работает разброс степеней, а не выбор партнёров.

Наименее вероятный и самый интересный: FLY обгоняет SHUFFLED.

Поскольку ожидаемый результат отрицательный, **все параметры оценки фиксируются в этом документе до первого прогона** (§6). Это не бюрократия: при отрицательном ожидании соблазн подкрутить метрику постфактум максимален, и без предрегистрации любой положительный результат окажется недоказуемым.

## 3. Факты, проверенные на данных

Всё ниже измерено непосредственно из `body-annotations` и `connectome-weights`, не взято из литературы.

| Факт | Значение |
|---|---|
| Клетки Кеньона (KC) | 4064 (L: 2045, R: 2019) |
| Проекционные нейроны (ALPN) | 686, подписаны по гломерулам |
| Обонятельные рецепторные нейроны (ORN) | 2639, подписаны по гломерулам |
| MBON | 97 |
| APL (тормозный) | 2, по одному на полушарие |
| Рёбра PN→KC | 22 586 (390 928 синапсов) |
| Среднее число входов на KC | 5.92 (медиана 6) |
| Рёбра APL→KC | 4633, охватывают 4063 KC из 4064 |

**До клеток Кеньона доходят не все ALPN, а только 282 из 686.** Остальные проецируются в латеральный рог, минуя грибовидное тело. Это соответствует литературе: в грибовидное тело идут унигломерулярные PN, которых около 150 на полушарие.

После фильтрации (порог веса ≥3, исключение KC с числом входов <2) рабочая схема выглядит так:

| Полушарие | KC | PN | Рёбер | Входов на KC | Экспансия |
|---|---|---|---|---|---|
| Левое | 1865 | 149 | 10 395 | 5.57 | 12.5× |
| Правое | 1875 | 143 | 10 341 | 5.52 | 13.1× |

Каждое грибовидное тело почти полностью одностороннее: из 149 входных PN слева 143 ипсилатеральны и лишь 6 приходят с противоположной стороны (справа — 138 из 143). Это подтверждает законность контроля из §4: полушария действительно можно считать независимыми экземплярами.

**Среднее 5.92 совпадает с литературным «~6 клешней на клетку»** — независимое подтверждение того, что извлечение корректно.

**Подтипы KC систематически различаются** по числу входов (порог веса ≥3):

Колонка «с входом» — число клеток подтипа, получающих хотя бы одно ребро PN→KC при пороге веса ≥3 (не общее число клеток подтипа).

| Подтип | с входом | Среднее число входов |
|---|---|---|
| KCg-m | 1336 | 6.65 |
| KCab-s | 656 | 5.64 |
| KCab-m | 535 | 4.81 |
| KCab-c | 487 | 4.74 |
| KCa'b'-ap2 | 291 | 5.02 |
| KCa'b'-m | 205 | 4.75 |
| KCa'b'-ap1 | 198 | 3.59 |
| KCab-p | 42 | 1.76 |
| KCg-d | 21 | 1.95 |

Разброс почти двукратный (6.65 против 3.59). В идеализированной модели такой гетерогенности нет вообще — это и есть первый кандидат на объяснение любой найденной разницы.

**KCg-d практически не получает обонятельного входа** (1.95). Это зрительные клетки Кеньона — у дрозофилы такие есть. Их присутствие в матрице создало бы молчащие единицы; исключаются явно (§6).

**APL контактирует со всеми KC, но с сильно разными весами** (средний вес 42). То есть «победитель забирает всё» у настоящей мухи — глобальный, но **градуированный**, а не равномерный топ-k. Это второй кандидат на объяснение.

**Полушария почти идентичны по среднему** (5.54 слева против 5.45 справа) — то есть пригодны как контроль.

## 4. Естественный контроль: два полушария

Левое и правое грибовидное тело — два экземпляра одной схемы, выращенные по одному генетическому рецепту в одной особи. Всё, что у них совпадает, задано развитием; всё, в чём они расходятся, — случайность сборки.

Разница FLY-L против FLY-R задаёт **естественную планку шума**. Разница FLY против SHUFFLED осмысленна только если она заметно больше этой планки. Без такой планки любой маленький эффект невозможно интерпретировать.

## 5. Архитектура

Четыре модуля, каждый тестируется независимо.

```
data/raw/*.feather  ──extract──>  circuit.npz  ──┐
                                                 ├──encode──>  коды  ──bench──>  отчёт
              MNIST / GloVe / SIFT  ──datasets──┘
```

### 5.1 `extract`

**Вход:** два feather-файла (14 МБ + 1002 МБ).
**Выход:** `circuit.npz` — несколько мегабайт, коммитится в репозиторий.

Содержит: разреженную матрицу PN→KC, вектор весов APL→KC, метаданные (id, тип, гломерула, полушарие для каждого PN и KC), матрицу ORN→PN для второго уровня входа.

Гигабайты читаются **ровно один раз**. Всё остальное работает с `circuit.npz`, поэтому эксперимент воспроизводим без скачивания 1 ГБ.

### 5.2 `models`

Пять реализаций одного интерфейса `project(X) -> активности KC`. Все дают матрицу одинаковой формы, поэтому сравнимы напрямую.

| Модель | Что это | Что проверяет |
|---|---|---|
| `FLY-L` | настоящая матрица, левое полушарие | вопрос |
| `FLY-R` | настоящая матрица, правое полушарие | вопрос + планка шума |
| `SHUFFLED` | конфигурационная модель: сохранены и число входов каждой KC, и число выходов каждого PN; перемешаны только пары | **ключевой контроль** — партнёры против степеней |
| `UNIFORM` | идеализация из статьи: ровно 6 случайных входов на KC | сравнение с опубликованным |
| `LSH` | плотная гауссова проекция + знак | базовый уровень |

`SHUFFLED` реализуется как двудольная конфигурационная модель (edge-swap рандомизация с сохранением обеих последовательностей степеней).

### 5.3 `encode`

```
x  ──нормализация──>  сжатие  ──проекция──>  WTA  ──>  разреженный бинарный код
```

- **Нормализация:** деление на среднее по вектору. Это имитация усиления в ORN и воспроизводит статью.
- **Сжатие:** гауссова случайная проекция d → n_pn, где n_pn — число PN, реально доходящих до KC этого полушария (149 слева, 143 справа); либо d → 58 на уровне гломерул (фаза 2). **Случайная, а не PCA** — принципиально: PCA зависит от данных и мог бы по-разному взаимодействовать с разными моделями проекции. Случайная проекция data-independent.
- **Матрица сжатия одна на полушарие** (seed 0) и **используется всеми пятью моделями без исключения**. Её вклад одинаков везде и при сравнении моделей вычитается. Это главный механизм защиты от «измерили сжатие вместо мухи».
- **WTA:** глобальный топ-k (основной вариант) либо градуированное торможение через веса APL (фаза 2).

### 5.4 `bench`

Для каждого запроса: эталонное множество — истинные ближайшие соседи полным перебором; предсказание — ранжирование по перекрытию кодов. Метрика — mAP (§6).

## 6. Предрегистрация

Эти значения зафиксированы **до первого прогона**. Любое отклонение отмечается в отчёте как апостериорный анализ.

| Параметр | Значение |
|---|---|
| Порог веса синапса | **≥ 3** (основной); 1, 5, 10 — только как проверка устойчивости |
| Исключение KC | KC с числом входов PN < 2 при пороге ≥3 исключаются; итоговое число фиксируется в отчёте |
| Длина хеша (доля активных KC) | **5%** (основная); 2%, 10%, 20% — разведочные. При 5% это 93 активные KC слева и 94 справа |
| Единица анализа | **полушарие**. Для каждого из L и R строятся FLY, SHUFFLED, UNIFORM, LSH одинаковой формы (n_kc × n_pn этого полушария). Основные сравнения: FLY-L против SHUFFLED-L и FLY-R против SHUFFLED-R |
| Размер базы | 10 000 объектов |
| Число запросов | 1000, seed 1 |
| Эталон | топ-100 истинных соседей: евклидово расстояние (MNIST, SIFT), косинус (GloVe) |
| Метрика | **mAP@100** |
| Число перемешиваний SHUFFLED | **100**, seeds 1000–1099 |
| Критерий значимости | FLY считается лучше SHUFFLED, только если её mAP выше 97.5-го процентиля распределения из 100 перемешиваний (двусторонний, α = 0.05) |
| Наборы данных | MNIST, GloVe, SIFT-10K — те же, что в статье 2017 |

Все seed'ы фиксированы; любой прогон воспроизводим побитово.

## 7. Фазы

**Фаза 1 — минимальный честный ответ.**
`extract` → `models` → `encode` → `bench`. Только MNIST, только уровень PN, только топ-k WTA. Все пять моделей. На выходе — число и вывод по основному вопросу.

**Фаза 2 — полнота.**
GloVe и SIFT. Второй уровень входа (58 гломерул, с полным контуром ORN→PN). Градуированное торможение через APL. FLY-L против FLY-R. Проверки устойчивости по порогу и длине хеша.

**Фаза 3 — библиотека.**
Только если муха себя показала. Устанавливаемый пакет с зашитой матрицей: кодирование векторов, поиск похожего, поиск дубликатов.

## 8. Риски

| Риск | Смягчение |
|---|---|
| Измерим сжатие входа, а не проводку | Одна матрица сжатия на все модели (§5.3) |
| Подкрутим метрику под желаемый результат | Предрегистрация (§6) |
| Разброс степеней выдадим за отбор партнёров | SHUFFLED сохраняет степени (§5.2) |
| Маленький эффект примем за настоящий | Планка шума FLY-L / FLY-R (§4) |
| Зрительные KC добавят молчащих единиц | Явное исключение по порогу входов (§6) |

## 9. Стек

Python, numpy + scipy.sparse, pyarrow для чтения feather, pytest. Никаких фреймворков глубокого обучения: все операции — разреженные умножения и сортировки.
